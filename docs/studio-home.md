# OneStep Studio 홈

2026-10-17. 한국어·영어·일본어 홈페이지의 개선 범위다. 각 게임 소개 페이지의 세계관과 플레이 요소는 유지한다.

- 첫 화면과 푸터의 문장은 ‘Better games, one step at a time.’이다. 한국어 소개는 ‘조금 느리더라도, 더 나은 게임을 향해 꾸준히 한 걸음씩 나아갑니다.’로, 속도보다 꾸준한 개선을 담는다. 영어·일본어 소개도 같은 의미로 쓴다. 두 게임의 채택 원화를 중심에 두고 큰 로고와 중복 영문 라벨·장식용 번호는 덜어 게임이 첫 화면 안으로 들어오게 한다.
- 사용자 다크 테마 지시에 따라 스튜디오 바탕은 `#0b1218`, 글자는 `#e6ecef`, 보조 글자는 `#a2b2bd`, 구분선은 `#293944`다. 하단 소개는 `#101e28`로 옅게 분리한다. 제목의 크기와 상단 여백도 줄여 게임 원화가 더 일찍 보이게 한다. 로고·메뉴·상태 표시·키보드 포커스·건너뛰기 링크도 어두운 배경에 맞춘다.
- 제목과 본문은 기존 게임 프로젝트의 Pretendard를 웹용으로 서브셋한 Studio Sans를 사용한다. 큰 제목 600, 본문 400. 일본어 글리프는 일본어 시스템 서체로 보완한다. `assets/studio/font-sources.json`에 원본 해시를 보존한다.
- 두 게임은 원화·소개·출시 상태를 한 장에 담은 카드로 구분한다. 타이니 디펜스는 남색 바탕과 -1.3도, 암행어사는 따뜻한 먹색 바탕과 +1.15도로 서로 다른 방향으로 살짝 기울인다. PC는 나란한 두 작품을 약간 다른 너비와 높이로 배치하고, 모바일에서는 한 작품씩 읽으며 기울기를 -0.65도·+0.7도로 줄인다. 테두리·내부 여백·그림자로 카드 경계를 표시하며, 전체 카드가 해당 언어 게임 페이지로 연결된다.
- 타이니 디펜스는 `assets/brand-20261014/keyart-wide.webp`의 채택 원화다. 암행어사 홈 키아트는 배포관리의 `C:/OneStep/amhaeng-eosa/deploy-project.json` → `banner` → `docs/art/manager-keyart-20261017.png`가 기준이다. 이 PNG는 생성 원본과 SHA-256이 동일하다. `tools/build-home-keyart.py`가 크롭·축소 없이 1536×1024 전체를 무손실 WebP로 내보내고 디코딩된 RGBA 픽셀의 동일성까지 확인한다. 원본·출력 해시와 처리 내역은 `assets/amhaeng-eosa/manager-keyart-source.json`에 보존한다.
- 암행어사 이미지는 기본 상태에서 3:2와 `object-fit:contain`으로 전체를 표시한다. 그림 안의 제목을 그대로 사용하며 별도 로고·명암 그라데이션을 덮지 않는다. 게임 전용 페이지의 로비·조사 화면은 별도 자료로 유지한다.
- 두 게임의 원화는 마우스를 올리면 동일하게 1.025배까지 0.7초 동안 확대되고, 마우스를 떼면 원래 크기로 돌아온다. 기울어진 카드와 이미지 레이어는 데스크톱의 호버 가능한 환경에서 `will-change:transform`으로 미리 준비한다. 카드 본문에는 변형·필터 애니메이션을 적용하지 않는다. 공통 진입 화살표는 마우스 또는 키보드 포커스에 반응한다. 자동 슬라이드·숨겨진 콘텐츠·반복 등장 연출은 없으며 움직임 줄이기를 존중한다.
- 언어 선택은 모바일에서도 헤더에서 바로 찾을 수 있다. 메뉴는 기존 `script.js`의 열기·닫기·Escape·이동 시 닫힘을 그대로 사용한다.

홈 마크업은 `tools/build-home-pages.py`, 스타일은 홈에서만 로드하는 `home.css`가 소유한다. `tools/build-eosa-pages.py`는 `data-studio-home="2"` 표식을 확인해 새 홈을 이전 카드로 덮어쓰지 않는다. 키아트는 `tools/build-home-keyart.py`, 글꼴 원문을 추가하면 `tools/build-home-fonts.py`를 실행하고, 정적 미리보기·배포 준비는 `tools/build-static.py`로 한다.

## 제작·검수 기준 · 2026-10-19

홈·게임 소개 화면을 추가하거나 배치를 바꾸기 전에 목적, 주 행동, 정보 순서, 기존 부품·채택 원화, 해당 상태를 짧게 정한다. 홈의 첫 판단은 어떤 게임인지·출시 상태가 무엇인지·어디서 자세히 보는지다. 소개 페이지의 특징은 현행 게임 코드와 실제 플레이 화면으로 뒷받침한다. 공통 수치와 색은 현재 CSS에서 읽으며 별도 사본을 만들지 않는다.

- ko/en/ja 각각을 PC1440px·태블릿768px·모바일390px 세로에서 연다. 긴 제목·번역·언어 전환·출시 상태와 상세 페이지의 언어 경로를 확인한다. 320px 최소 너비에서도 가로 넘침을 확인한다.
- 첫 화면의 설명·게임 진입 동작, 모바일 메뉴의 열기·Escape·닫기·복귀와 키보드 포커스를 실제로 조작한다. 호버 없이도 게임·출시 상태·진입 방법이 읽혀야 한다.
- 실제 원화의 구도·색·제목·인물을 확인한다. 암행어사의3:2 전체 구도·원본 픽셀, 두 게임의 이미지 호버와 본문 정지, 움직임 줄이기 계약을 유지한다.
- 최종 캡처를 직접 열어 글자 잘림·겹침·작은 상태 문구·과한 빈 공간과 그림/주 행동의 위계를 함께 본다. 자동 검사만으로 디자인 완성도를 판정하지 않는다.
- 저장소의 관련 테스트와 정적 배포 자산을 검사하고, 새 미리보기는 비공개 Tailscale의 실제 페이지·미디어 응답까지 확인한다. 확인한 크기·언어·동작과 미확인 범위를 구분해 기록한다.

`impeccable`·`frontend-design`·`ux-writing`에서 이 목적에 맞는 기준을 적용한다. Taste Skill의 스타일 선택은 새 시안이 필요한 작업의 비교 수단으로만 사용한다. 정해진 섹션·이미지·애니메이션 개수를 채우려고 현재 구성을 늘리거나 기존 원화·호버 계약을 바꾸지 않는다.
